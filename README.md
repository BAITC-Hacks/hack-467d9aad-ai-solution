# 1. Название проекта

**StudyForge — помощник по материалам лекций**

## 2. Краткое описание: проблема и аудитория

После лекции студенту приходится вручную выделять главное, составлять вопросы и карточки, а затем сверять их с исходным материалом. StudyForge помогает студентам и другим учащимся сделать этот первый проход: принимает текст лекции и формирует конспект, ключевые тезисы, тест с правильными ответами и карточки для повторения. Для тезисов, вопросов и карточек интерфейс также показывает дословные цитаты из лекции.

## 3. Что реализовано

- ввод текста лекции и встроенный пример для демонстрации;
- четыре вида результата: конспект, тезисы, тест и flashcards;
- правильные ответы к вопросам теста;
- `source_quote` для тезисов, вопросов и карточек;
- серверная проверка наличия каждой такой цитаты в исходной лекции;
- счётчик подтверждённых цитат и удаление элементов с неподтверждёнными цитатами;
- проверка длины ввода от 200 до 50 000 символов;
- состояния загрузки и ошибки, повторная обработка, адаптивный интерфейс;
- два режима обработки: предпочтительный OpenAI AI mode и локальный deterministic fallback;
- автоматические тесты валидации, fallback и серверного маршрута.

## 4. Как работает: пользовательский сценарий

1. Пользователь нажимает **«Заполнить пример»** или вставляет текст своей лекции.
2. Нажимает **«Создать материалы»**.
3. Браузер отправляет текст на `POST /api/generate`.
4. Сервер использует OpenAI Responses API, если настроены `OPENAI_API_KEY` и `OPENAI_MODEL`. Без полной конфигурации, а также при ошибке API или непрошедшем валидацию ответе сервер использует локальный deterministic fallback.
5. Сервер проверяет структуру результата и наличие `source_quote` в исходном тексте, нормализуя только пробелы и регистр. Неподтверждённые элементы удаляются.
6. Пользователь видит активный режим и четыре вкладки: **«Конспект»**, **«Тезисы»**, **«Тест»**, **«Карточки»**. В последних трёх можно раскрыть источник в лекции.

Локальный fallback использует детерминированные extractive-эвристики над текстом лекции. **Fallback не является AI** и не обозначается как AI в интерфейсе.

## 5. Технологии

- **Node.js 20+**, CommonJS;
- встроенные модули Node.js: `node:http`, `node:fs`, `node:path`; для тестов — `node:test`, `node:assert`, `node:stream`;
- браузерные **HTML, CSS и JavaScript** без frontend-фреймворка;
- **OpenAI Responses API** — опциональный, предпочтительный AI-режим;
- встроенный `fetch` и `AbortSignal.timeout` Node.js для серверного API-запроса;
- deterministic local fallback без внешнего API и без AI;
- внешние npm-зависимости отсутствуют.

При разработке проекта использовался AI-агент **Codex**. Это инструмент разработки, а не отдельная runtime-интеграция продукта.

## 6. Архитектура и компоненты

- `public/index.html`, `public/styles.css`, `public/app.js` — интерфейс, ввод лекции, запрос к API и отображение четырёх типов материалов;
- `server.js` — HTTP-сервер, раздача статических файлов, маршрут `POST /api/generate`, вызов OpenAI Responses API и переключение на fallback;
- `lib.js` — проверка длины лекции, разбор JSON, локальная генерация и grounding-валидация цитат;
- `tests/lib.test.js`, `tests/server.test.js` — unit- и server-level тесты.

AI-путь: `браузер → Node.js server → OpenAI Responses API → JSON → grounding validator → UI`.

Локальный путь: `браузер → Node.js server → deterministic extractive fallback → grounding validator → UI`.

## 7. Установка и запуск

Требуется Node.js 20+. Устанавливать npm-пакеты не нужно: у проекта нет внешних зависимостей.

### Без API: воспроизводимый локальный fallback

```bash
npm start
```

Откройте `http://localhost:3000`. Не задавайте `OPENAI_API_KEY` и `OPENAI_MODEL`: интерфейс покажет `Offline fallback · без API`. Этот режим локальный и детерминированный, но не AI.

### С OpenAI: предпочтительный AI-режим

```bash
export OPENAI_API_KEY="<ваш API-ключ>"
export OPENAI_MODEL="<доступная вам модель>"
npm start
```

Откройте `http://localhost:3000`. При успешном ответе API интерфейс покажет `AI mode · OpenAI`. Обе переменные обязательны для этого режима. API-ключ читается только сервером и не отправляется в браузер. Если API недоступен или его ответ не проходит проверку, приложение продолжит работу в явно помеченном локальном fallback.

Для другого порта можно задать `PORT`, например `PORT=8080 npm start`.

## 8. Как проверить: воспроизводимая демонстрация

Проверка не требует API-ключа:

```bash
npm test
npm start
```

Затем:

1. Откройте `http://localhost:3000`.
2. Нажмите **«Заполнить пример»**, затем **«Создать материалы»**.
3. Убедитесь, что виден badge `Offline fallback · без API` и четыре вкладки результата.
4. Переключитесь между конспектом, тезисами, тестом и карточками.
5. В тезисах, тесте и карточках раскройте **«Источник в лекции»** и сопоставьте цитату с исходным текстом.
6. Проверьте счётчик подтверждённых цитат и кнопку **«Другая лекция»**.

## 9. Данные и интеграции

- входные данные — текст лекции, который пользователь вставляет в браузере;
- браузер отправляет текст только на серверный маршрут проекта;
- в OpenAI-режиме сервер передаёт текст лекции в OpenAI Responses API;
- в fallback-режиме обработка выполняется локально сервером без внешнего API;
- результаты возвращаются как JSON и отображаются в браузере;
- база данных, учетные записи, загрузка файлов и постоянное хранение данных не реализованы;
- секреты не хранятся в репозитории: OpenAI API key передаётся процессу через переменную окружения.

## 10. Ограничения

- OpenAI AI mode требует сетевого доступа, действительных `OPENAI_API_KEY` и `OPENAI_MODEL`; доступность выбранной модели зависит от среды запуска;
- локальный fallback ограничен extractive-эвристиками, не является AI и не заменяет качество LLM;
- прототип принимает только текст: speech-to-text, видео, чат и экспорт не реализованы;
- grounding-проверка подтверждает наличие цитаты, но не является полной оценкой качества или фактической полноты конспекта;
- конспект не содержит `source_quote`; цитаты предусмотрены для тезисов, теста и карточек;
- данные не сохраняются между перезапусками сервера и не синхронизируются между устройствами.
